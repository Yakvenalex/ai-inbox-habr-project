# AI Inbox

Локальный мультимодальный помощник для почты и задач на Python. Учебный проект для
статьи на Хабре в сотрудничестве с [AnyModel](https://anymodel.org/?ref=yakvenalex).

Почта → сводка → задача → локальный черновик → ежедневный дайджест. Изображение
можно приложить к чату, голос — расшифровать и исправить перед отправкой команды,
ответ или дайджест — озвучить и скачать MP3. Новое письмо можно отправить вручную
после проверки; агент **сам не отправляет письма**.

## Что работает

- IMAP: непрочитанные/все последние письма, текст, метаданные вложений и серверные
  счётчики. Открытие пользователем отмечает письмо прочитанным в почтовом ящике;
  статус можно вернуть и менять для выбранных писем. Агент и сводки читают без отметки.
  ID включает mailbox, UIDVALIDITY и UID.
- Задачи: создание, редактирование, завершение, фильтры статуса/срока, связь с источником.
- Черновики: создание из письма, отдельный редактор; хранятся только в локальной SQLite.
- Исходящие: адрес получателя, ручной или подготовленный ИИ текст, сохранение черновика,
  файлы-вложения и отправка после отдельного подтверждения. Есть локальная история.
- Чат: сохранённые диалоги, JPEG/PNG vision, восемь инструментов над общими use cases.
  Интерфейс показывает реальные результаты и ID отдельно от текста модели.
- Голос: микрофон или загрузка файла → ASR → редактирование → явная отправка текста.
  WebM/OGG/WAV/MP3/M4A нормализуются в OGG Opus через ffmpeg. Ответы и дайджесты → MP3.
- Ручной и ежедневный дайджест: по умолчанию 09:00 Europe/Moscow, текст, источники,
  состояние генерации, озвучка. Один плановый дайджест за локальную дату.
- Вход: один владелец из окружения; JWT Bearer в API/Swagger, HttpOnly-cookie и CSRF в UI.
- Тёмный интерфейс с графитовой палитрой, форматирование Markdown в сводках,
  ответах и дайджестах; сводку можно убрать крестиком вместе с её аудиоплеером.
- Jinja2, Tailwind 4 Play CDN, daisyUI 5 CSS через CDN; Node.js и frontend-сборка не нужны.

## Установка и запуск

Требуются Python 3.12+ (проверено на 3.13), [uv](https://docs.astral.sh/uv/),
ffmpeg и ffprobe в PATH. Интернет нужен для IMAP, AnyModel и CDN.

```bash
git clone https://github.com/Yakvenalex/ai-inbox-habr-project.git
cd ai-inbox-habr-project
uv sync --frozen --python 3.13
cp .env.example .env
```

Копирование `.env.example` нужно только при новой установке. **Не перезаписывай
существующий `.env`.** Заполни его собственными значениями:

- `MAIN_KEY`, `BASE_URL` и полные идентификаторы моделей с префиксами.
- `MAIL_USER`, `MAIL_PASS`: адрес и пароль приложения для IMAP по TLS.
- `AUTH_USERNAME`, `AUTH_PASSWORD`: отдельный локальный вход, отличный от почты.
- `JWT_SECRET_KEY`: независимый случайный секрет минимум 32 байта. Для генерации:
  `python -c "import secrets; print(secrets.token_urlsafe(48))"`.

```bash
uv run alembic upgrade head
uv run python -m ai_inbox
```

Приложение: [127.0.0.1:18763](http://127.0.0.1:18763).
Swagger: [127.0.0.1:18763/docs](http://127.0.0.1:18763/docs).
Минимальный `/health` не обращается к платным сервисам.

Настройки и относительные пути SQLite/media разрешаются от корня проекта независимо
от текущего каталога. Значения секретов не выводятся. При отсутствующих, шаблонных
или некорректных credentials приложение объяснит ошибку старта. При недостающей
миграции попросит выполнить Alembic. Для запуска из другого каталога используй
`uv run --directory /путь/к/проекту python -m ai_inbox`.

Запускай **один процесс**, без `--reload` и нескольких workers. Остановка — Ctrl+C;
для проверки новых изменений останови процесс и запусти снова. БД и media сохраняются.
Для резервной копии останови приложение и скопируй каталог `data/` в безопасное место.

## Первый сценарий

1. Войди с логином/паролем из своего `.env`. Открой письмо и прочитай текст: после
   подтверждения сервером оно станет прочитанным и исчезнет из «Непрочитанных».
   В окне есть «Отметить непрочитанным», а флажки списка позволяют менять статус группы.
2. Нажми «Сделать сводку» (можно выбрать несколько писем флажками).
3. Чтобы написать новое письмо, открой «Написать письмо», укажи адрес. Заполни тему
   и текст сам либо раскрой «Помочь написать письмо» и введи набросок. Можно приложить
   до 10 файлов суммарно до 15 МБ. «Проверить и отправить» показывает получателя,
   содержание и список файлов; письмо уходит только после «Отправить письмо».
4. Создай задачу из письма кнопкой «В задачу» либо попроси ассистента. При сроке
   укажи дату, время и часовой пояс. Дата без времени требует уточнения.
5. Создай локальный черновик и отредактируй его на отдельной странице.
6. Прикрепи `tests/fixtures/invoice.png` и напиши: «Создай задачу проверить учебный
   счёт по изображению. Сохрани номер, сумму с копейками и указанный срок».
7. Запиши или загрузи голос, проверь текст, нажми «Перенести в сообщение», затем
   отдельно отправь его. Для записи браузер запросит микрофон; localhost позволяет
   использовать этот API. Если запись недоступна, остаётся загрузка аудиофайла.
8. Создай дайджест и нажми «Озвучить». MP3 доступен через защищённый плеер и скачивание.

Действия с моделями платные. Сводки и дайджесты передают выбранные письма AnyModel.
Для демонстраций используй синтетические данные; не снимай реальные письма/секреты.

## Swagger и API

Нажми **Authorize** в `/docs`, введи логин и пароль своего приложения. Swagger вызывает
`POST /api/v1/auth/token` с form-urlencoded и добавляет Bearer к запросам. Endpoint
не ставит cookie; авторизация Swagger не сохраняется после перезагрузки страницы.

Группы API: `/auth`, `/emails`, `/tasks`, `/drafts`, `/conversations`, `/files/images`,
`/speech/transcriptions`, `/speech/synthesis`, `/digests`, `/media`, `/outbox`. Все находятся под
`/api/v1`. Схемы, синтетические примеры, успешные ответы и ошибки описаны в OpenAPI.

`POST /conversations/{id}/messages` принимает `text`, необязательный `image_id` и
обязательный UUID `request_id`. Повтор того же запроса с тем же ID возвращает
сохранённый результат. При сетевой ошибке повторяй **тот же** ID. Ответ содержит
`status`, `text`, `actions`, `message_id`, `error`; failed означает незавершённый
ответ, но успешные действия внутри `actions` уже сохранены. Новый ID — новое намерение.

Ошибки API: `{"error":{"code":"…","message":"…"}}`. Неверная авторизация — 401,
CSRF — 403, отсутствующий объект — 404, конфликт — 409, загрузка сверх лимита — 413,
ошибка данных — 422, ошибка протокола/лимита агента — 502, недоступный провайдер — 503. Реальный HTTP 429/503/524 упоминается
в безопасном сообщении, внутренние ответы и секреты провайдера не возвращаются.

Bearer имеет приоритет над cookie: ошибочный header не переключается на валидную
cookie. Cookie-записи требуют правильного Origin и `X-CSRF-Token` из отдельной
CSRF-cookie. JWT никогда не хранится в JS, localStorage, query string или URL MP3.
Выход удаляет cookie, но ранее скопированный Bearer действует до exp (по умолчанию 60 минут).
При HTTPS включи `AUTH_COOKIE_SECURE=true`. Проект предназначен для локального запуска.

## Архитектура

`domain` — dataclasses, статусы, сроки и ошибки; без ORM, SDK, HTTP и `.env`.
`application` — use cases, DTO и Protocol-порты; не знает FastAPI и SQLAlchemy.
`infrastructure` — SQLite/UoW, IMAP, AnyModel/Agents SDK, JWT, файлы и расписание.
`presentation` — тонкие API-роутеры, Jinja2 и небольшой браузерный JS.
`bootstrap` — конфигурация, composition root и жизненный цикл.

API, UI и SDK tools вызывают одни сценарии. Сетевые вызовы выполняются вне транзакций.
IMAP работает в ограниченном thread pool; конвертация аудио — отдельным subprocess
без shell и пользовательских имён путей. Никаких Redis, Celery или MCP. SMTP SSL выполняется в ограниченном thread pool.

LLM использует `OpenAIChatCompletionsModel`; tracing в OpenAI отключён. SDK retries
выключены, собственные повторы ограничены двумя попытками на запрос к провайдеру.
Действие и его квитанция записываются атомарно. Ключи request/call и семантический
ключ предотвращают повтор одинакового действия в одном запросе. После перезапуска
прерванные ответы получают failed с сохранёнными результатами.

## Проверки и безопасная демонстрация

```bash
uv run pytest -q
uv run ruff check src tests scripts migrations
uv run ruff format --check src tests scripts migrations
uv run mypy
uv run alembic check
```

Обычные тесты запрещают внешние соединения, используют fake gateways и временную БД.
Они не читают настоящий `.env`, не расходуют баланс и не отправляют писем.

Отдельные **платные** opt-in smoke-проверки (все либо только нужный флаг):

```bash
uv run python scripts/smoke.py --mail --ai --speech
```

Mail читает ограниченную выборку и сравнивает флаги. AI проверяет синтетический счёт,
настоящий вызов инструмента и запись в временную SQLite. Speech получает настоящий
MP3 и распознаёт его после конвертации в WebM. Результаты в `data/smoke/`, вне Git.
Временная недоступность провайдера выдаётся отдельно от ошибки проверяемого поведения.

Для скриншотов и повторения UI-сценариев без расходов:

```bash
uv run python -m tests.e2e.demo_server
```

Демостенд: [127.0.0.1:18764](http://127.0.0.1:18764), логин `demo`, пароль
`demo-inbox-only`. Он явно помечен, использует только синтетическую почту и тестовые
адаптеры из tests, не читает `.env`. Демо-MP3 — тон; это проверка плеера, не качества голоса.
Рабочее приложение на 18763 всегда использует настоящие адаптеры.

## Прочитано и непрочитано

Просмотр текста остаётся безопасным `GET /api/v1/emails/{id}` без изменения состояния.
После показа письма интерфейс отдельно вызывает `POST /api/v1/emails/{id}/read-state`
с `{ "unread": false }`. Для обратной отметки передай `true`. Это IMAP, а не SMTP:
адаптер меняет только `\Seen` через UID STORE и подтверждает результат отдельным FETCH.
Остальные флаги не переписываются; команды удаления и EXPUNGE не вызываются.

`GET /api/v1/emails/status` возвращает серверные `total` и `unread` для INBOX.
`POST /api/v1/emails/read-state` принимает `ids` (до 20) и boolean `unread`.
В `results` возвращается подтверждённый статус или ошибка каждого письма: групповая
операция не атомарна. Источником статуса служит IMAP, отдельной SQLite-копии нет.
Ошибки сети/сервера отображаются, успешная отметка не имитируется локально.
В другом почтовом клиенте может понадобиться обновить список; здесь есть «Обновить».

У агента нет инструмента изменения прочитанности. Сводки, дайджесты, подготовка
черновика и обычный API GET по-прежнему используют readonly/BODY.PEEK.

Отдельная opt-in проверка на реальном ящике без платных моделей и без отправки:

```bash
uv run python scripts/smoke.py --mail-read-state
```

Она кратковременно переключает `\Seen` одного последнего письма, проверяет его
с другого соединения и возвращает исходное значение в finally. Остальные флаги
не меняются. При невозможности подтвердить восстановление команда завершится ошибкой
с просьбой проверить статус вручную. Обычные тесты реальные флаги не трогают.

## Отправка писем

«Исходящие» содержит отдельные исходящие черновики и результаты попыток. Редактор
существующего ответного черновика имеет ссылку «Подготовить к отправке»: текст переносится
в новое письмо, адрес получателя ты указываешь сам. Получатель один; CC/BCC пока нет.
Можно также попросить чат: «Подготовь письмо для reader@example.com по наброску …».
Агент сохранит черновик и даст ссылку на проверку, без отправки.

Файлы загружаются через `POST /api/v1/files/attachments`; любые типы сохраняются
в непрозрачные UUID-файлы и выдаются только как скачивание после авторизации.
Их содержимое не передаётся ИИ. Лимит — 10 файлов и 15 МБ суммарно (до MIME-кодирования);
так остаётся запас на base64 и заголовки. Фактический лимит SMTP-сервера может быть ниже.

API-сценарий: `/outbox/compose` готовит только тему/текст → `POST /outbox` сохраняет
письмо → `GET /outbox/{id}` позволяет проверить содержимое → `POST /outbox/{id}/send`
с `confirmed=true`, новым UUID `request_id` и `content_token` из проверенного ответа.
Если письмо изменилось после проверки, сервер вернёт 409. Cookie-запросы защищены CSRF.
Повтор той же попытки возвращает её прежнюю квитанцию и не вызывает SMTP заново.

Статусы: draft → sending → sent / failed / unknown. **sent означает приём письма
SMTP-сервером, а не доказанную доставку получателю.** При определённом отказе failed
можно исправить письмо или явно повторить с новым request_id. При неизвестном результате
(обрыв в DATA или остановка приложения) автоматическая и повторная отправка заблокированы:
нужно проверить получение. Это защита от дубля, а не обещание exactly-once в SMTP.

SMTP использует MAIL_SMTP_HOST/PORT и существующие MAIL_USER/MAIL_PASS с проверкой TLS.
Один запрос — одна SMTP-попытка без скрытых retries. Отправляется обычный текст с MIME-
вложениями, HTML-тело не генерируется. Копия и вложения остаются в локальных «Исходящих»;
приложение отдельно не делает IMAP APPEND в папку Sent внешнего провайдера.

Проверка соединения без письма и opt-in платные проверки новых AI-сценариев:

```bash
uv run python scripts/smoke.py --smtp
uv run python scripts/smoke.py --compose --outgoing-agent
```

SMTP smoke делает только TLS/login/NOOP. AI smoke использует синтетический набросок
и временную SQLite. Ни одна из этих команд не отправляет письма.

## Модели и ограничения

Выбраны `ag/gemini-3.8-flash-low` (LLM/vision), `dg/nova-3` (русская ASR),
`anyvoice/builtin-7` («Спокойный женский», TTS). Все IDs задаются окружением.
Голос AnyModel задаётся model ID; поле voice не отправляется. Автоматический fallback
не включён: резерв требует повторной проверки. Названия, цены и доступность маршрутов
перед публикацией статьи нужно проверить заново.

- Один владелец, INBOX, локальная SQLite, один процесс; регистрации и refresh-токенов нет.
- Компьютер и процесс должны работать в момент расписания. Нет рассылки, запуска во
  сне/после выключения и очереди старых дайджестов. Окно пропуска — максимум час.
- Изображения: JPEG/PNG до MAX_UPLOAD_MB и 20 млн пикселей. Почтовое сообщение — до
  2 МБ, текст для модели ограничен; вложения показываются как метаданные.
- Аудио: до MAX_UPLOAD_MB (по умолчанию 20 МБ) и 5 минут. Озвучка одного текста —
  до 5000 символов. Сгенерированные MP3 удаляются через AUDIO_RETENTION_DAYS (7 дней),
  изображения и другие данные эта очистка не удаляет. Озвучку дайджеста можно повторить.
- Чат возвращает готовый JSON-ответ, без streaming. Активный контекст ограничен
  последними 12 пользовательскими ходами; история хранится в SQLite.
- Простая проверка намерения может попросить явную команду «создай задачу» или
  «подготовь черновик». Она дополняет prompt, но не гарантирует полной защиты от
  prompt injection. Всегда проверяй суммы, сроки и результат перед реальным действием.
- Нельзя гарантировать восстановление алфавита визуально одинаковых букв по картинке.
  В реальной smoke-проверке проверялись различимые «ЖЮ». WER для ASR не измерялся.
- Tailwind Play CDN официально предназначен для разработки; здесь выбран сознательно.
  Закреплены Tailwind browser 4.1.18, daisyUI 5.7.50, Marked 17.0.1 и DOMPurify 3.4.17.
  Markdown очищается перед вставкой, внешний HTML выводится текстом; картинки
  из ответов автоматически не загружаются. CDN требует интернета.
- После неудачного планового дайджеста автоматического платного повтора в тот же день
  нет. Ошибка видна в истории; ручная генерация создаёт отдельный дайджест.

`.env`, локальная спецификация, БД, реальные письма, вложения, аудио, логи и артефакты
исключены из Git. Публикуются только код, безопасный `.env.example` и синтетические fixtures.
