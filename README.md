# AI Inbox

Локальный мультимодальный помощник для почты и задач на Python. Учебный проект
в сотрудничестве с [AnyModel](https://anymodel.org/?ref=yakvenalex).

Прочитать письма, получить сводку, извлечь задачу из фотографии, продиктовать
команду, подготовить ответ и собрать дайджест — в одном веб-интерфейсе.
Агент выбирает инструменты по контексту диалога. Новое письмо сначала показывается
как черновик и отправляется после отдельного подтверждения владельца.

## Возможности

- **Почта:** входящие с пагинацией, прочитанные/непрочитанные письма, сводки и ссылки
  на источники. Открытие письма в интерфейсе меняет статус на IMAP-сервере;
  агент, сводки и дайджесты читают без изменения флагов. Есть групповые действия
  и подтверждённый перенос в серверную корзину.
- **Задачи:** создание, редактирование, завершение, фильтры, сроки с часовым поясом
  и источники из писем или изображений. При неполном сроке агент уточняет детали.
- **Письма и черновики:** ручное составление или помощь ИИ по наброску, один
  получатель, до 10 вложений суммарно до 15 МБ. Отправка через редактор или чат,
  локальная история и защита от повторной отправки.
- **Чат:** сохранённые диалоги, удаление с подтверждением, потоковые ответы,
  Markdown, статусы инструментов и отдельные квитанции выполненных действий.
  Перезагрузка страницы подключается к текущему запросу без повторного выполнения.
- **Изображения и голос:** JPEG/PNG → извлечение данных; микрофон или аудиофайл →
  расшифровка → редактирование → отправка текста. Ответы и дайджесты можно озвучить:
  автозапуск в браузере, кнопка остановки и скачивание MP3.
- **Дайджест:** ручной и ежедневный, с источниками, открытыми задачами и озвучкой.
- **API и вход:** Swagger, JWT Bearer для API, HttpOnly-cookie и CSRF для интерфейса.

Стек: FastAPI, OpenAI Agents SDK, SQLAlchemy, SQLite, Alembic, APScheduler,
Jinja2, Tailwind и daisyUI через CDN. Node.js и frontend-сборка для работы не нужны.

## Быстрый запуск

Нужны Python 3.12+ (проверено на 3.13), [uv](https://docs.astral.sh/uv/),
`ffmpeg` и `ffprobe` в PATH. Интернет нужен для почты, AnyModel и CDN.

```bash
git clone https://github.com/Yakvenalex/ai-inbox-habr-project.git
cd ai-inbox-habr-project
uv sync --frozen --python 3.13
cp .env.example .env
```

Копируй шаблон только при новой установке: существующий `.env` перезаписывать не нужно.
Заполни в `.env`:

- `MAIN_KEY`, `BASE_URL` и идентификаторы моделей AnyModel с префиксами маршрутов.
- `MAIL_USER`, `MAIL_PASS` — почтовый адрес и пароль приложения. В шаблоне настроены
  IMAP/SMTP Mail.ru по TLS; для другой почты укажи её серверы и порты.
- `AUTH_USERNAME`, `AUTH_PASSWORD` — отдельный вход в AI Inbox.
- `JWT_SECRET_KEY` — независимый случайный секрет минимум 32 байта.

Сгенерировать JWT-секрет можно командой
`python -c "import secrets; print(secrets.token_urlsafe(48))"`.
Пароль приложения, API-ключ, пароль почты и JWT-секрет должны различаться.

```bash
uv run alembic upgrade head
uv run python -m ai_inbox
```

- Приложение: [http://127.0.0.1:18763](http://127.0.0.1:18763).
- Swagger: [http://127.0.0.1:18763/docs](http://127.0.0.1:18763/docs).
- `/health` проверяет процесс без обращения к почте или платным API.

Запускай **один процесс**, без нескольких workers и `--reload`. Остановка — Ctrl+C.
После изменения `.env` перезапусти приложение. Пути SQLite и media разрешаются
от корня проекта. Для запуска из другого каталога:
`uv run --directory /путь/к/проекту python -m ai_inbox`.

## Модели и настройки

В шаблоне и значениях по умолчанию:

- `LLM_MODEL=cx/gpt-6.1-terra` — агент, сводки и работа с изображениями.
- `ASR_MODEL=dg/nova-3`, `ASR_LANGUAGE=ru` — распознавание речи.
- `TTS_MODEL=anyvoice/builtin-7` — озвучка AnyModel.

Эти маршруты использовались в ограниченных реальных проверках. Их доступность,
стоимость и возможности нужно уточнять перед использованием; название маршрута
само по себе не подтверждает подлинность модели или надёжность сервиса.
LLM-fallback выключен; `LLM_FALLBACK_ENABLED=true` в этой версии не поддерживается.
Поля `LLM_FALLBACK_MODEL` и `ASR_FALLBACK_MODEL` сохранены как настройки резерва,
автоматического переключения на них нет.

Ежедневный дайджест по умолчанию включён на **09:00 Europe/Moscow**.
Настройки: `DIGEST_ENABLED`, `DIGEST_HOUR`, `DIGEST_MINUTE`, `APP_TIMEZONE`.
Компьютер и приложение должны работать; задачи со сроком сами по себе не создают
отдельных push-уведомлений. После выключения компьютера очередь дайджестов не догоняется.

HTTP-клиенты AnyModel по умолчанию учитывают proxy и SSL_CERT_* из окружения.
Если системный прокси недоступен, `ANYMODEL_TRUST_ENV=false` включает прямое
подключение для этих клиентов с обычной проверкой TLS. Почту эта опция не меняет.
Остальные лимиты и параметры перечислены в [.env.example](.env.example).

## Сценарии для проверки

1. Открой входящие, получи сводку и перейди к письму по ссылке на источник.
   Можно отметить несколько писем флажками и составить сводку по ним.
2. Прикрепи [учебный счёт](tests/fixtures/invoice.png) и попроси:
   «Создай задачу проверить этот счёт со сроком из документа.
   В заметках сохрани номер и сумму с копейками». Проверь карточку задачи.
3. Продиктуй: «Напомни завтра связаться с поставщиком». Проверь расшифровку
   и отправь её. На уточнение времени ответь: «В половине десятого утра, по Москве».
4. Попроси: «Подготовь письмо для reader@example.test по наброску: приветствие
   и вопрос, как дела». Это учебный адрес, для реальной доставки укажи свой.
   Проверь черновик и отдельно подтверди отправку своими словами.
5. Создай дайджест, проверь сроки и источники, нажми «Озвучить». После подготовки
   звука эта же кнопка останавливает ожидание или воспроизведение.

Модель сама понимает подтверждение, отказ и просьбу внести правки по контексту;
словаря команд нет. Сервер проверяет версию показанного черновика, отдельный ход
подтверждения, статусы и идемпотентность. Новый показ или изменение письма требуют
нового подтверждения. Адрес нового получателя должен быть указан владельцем
в текущем или предыдущем сообщении этого диалога. При нескольких черновиках
нужно показать один конкретный. При недоступной модели остаётся ручная отправка
через редактор.

Действия с моделями платные. Сводки и дайджесты передают выбранные письма AnyModel;
изображения и голос обрабатываются внешними API. Для демонстраций используй
синтетические данные. Качество понимания и устойчивость к инструкциям внутри
писем зависят от модели: проверяй адрес, текст, суммы, сроки и вложения перед отправкой.

## API и Swagger

В `/docs` нажми **Authorize** и введи логин/пароль приложения. Swagger получает
JWT через `POST /api/v1/auth/token` и добавляет Bearer к запросам. Cookie при этом
не устанавливается; авторизация Swagger не сохраняется после перезагрузки страницы.
Веб-интерфейс использует отдельную HttpOnly-cookie, Origin и CSRF-проверки.

Все прикладные маршруты находятся под `/api/v1`: `/emails`, `/tasks`, `/drafts`,
`/conversations`, `/files`, `/speech`, `/digests`, `/media`, `/outbox`.
Схемы, примеры и ответы описаны в OpenAPI.

- `GET /emails/page?unread=false&limit=20` возвращает `items` и `next_cursor`.
  Для следующей страницы передай курсор в `before`. Старый `GET /emails` возвращает список.
- `GET /emails/{id}` не меняет статус; `POST /emails/{id}/read-state`
  с `{"unread": false}` отмечает прочитанным. Для группы есть `/emails/read-state`.
- `DELETE /emails/{id}` с `{"confirmed": true}` переносит письмо в серверную корзину.
  Для группы — `POST /emails/delete` с `ids` и `confirmed`. До 20 писем за операцию;
  результат группы содержит отдельные успехи и ошибки.
- `POST /conversations/{id}/messages` принимает `text`, UUID `request_id`
  и необязательный `image_id`. Вариант `/messages/stream` возвращает SSE.
  При переподключении используй тот же `request_id`, не создавай новую команду.
- `POST /outbox/compose` готовит тему и текст; `POST /outbox` сохраняет письмо.
  После проверки `GET /outbox/{id}` отправка через `POST /outbox/{id}/send` требует
  `confirmed=true`, UUID `request_id` и `content_token` проверенной версии.

Ответ чата содержит `status`, `text`, `actions`, `message_id`, `error`.
`failed` не отменяет уже выполненные действия: фактические результаты находятся
в `actions`. Ошибки API имеют вид `{"error":{"code":"…","message":"…"}}`.
Коды: 401 — вход, 403 — запрет/CSRF, 404 — объект не найден, 409 — конфликт,
413 — размер, 422 — данные, 502 — протокол агента, 503 — внешний сервис.

**Статус `sent` означает приём SMTP-сервером, а не подтверждённую доставку.**
`failed` допускает новую явную попытку после проверки, `unknown` блокирует повтор:
сервер мог принять письмо до обрыва соединения. Скрытых SMTP retries нет.
Копия хранится в локальных исходящих, отдельного IMAP APPEND в папку Sent нет.

## Архитектура

```text
src/ai_inbox/
  domain/          # сущности и бизнес-ограничения
  application/     # сценарии, порты, инструменты агента
  infrastructure/  # SQLite, IMAP/SMTP, AnyModel, JWT, файлы, расписание
  presentation/    # FastAPI API, Jinja2, браузерный JavaScript
  bootstrap/       # настройки и сборка зависимостей
migrations/        # Alembic
scripts/           # opt-in реальные smoke-проверки
tests/             # unit, integration, frontend, e2e и синтетические fixtures
```

Domain не зависит от фреймворков; application определяет порты. API и инструменты
агента вызывают одни сценарии. Сетевые операции выполняются вне транзакций.
Tracing Agents SDK в OpenAI отключён. Зависимости закреплены в `uv.lock`.
Обоснования и детали: [docs/decisions.md](docs/decisions.md).

## Проверки

```bash
uv sync --frozen --python 3.13
uv run pytest -q
uv run ruff check src tests scripts migrations
uv run ruff format --check src tests scripts migrations
uv run mypy
uv run alembic check
node --test tests/frontend/*.test.cjs
```

Node.js нужен только для JS-тестов. Обычные тесты используют временную SQLite,
тестовые адаптеры и запрет внешних соединений: баланс и реальная почта не затрагиваются.
`alembic check` требует заполненный `.env` и применённые миграции.

Опциональные проверки с настоящими адаптерами:

```bash
uv run python scripts/smoke.py --mail --smtp
uv run python scripts/smoke.py --ai --stream
uv run python scripts/smoke.py --speech
uv run python scripts/smoke.py --compose --outgoing-agent --chat-send
```

AI и speech-проверки **платные**, используют синтетические входы и временную БД.
`--mail` читает ограниченную выборку без изменения флагов; `--smtp` делает TLS/login/NOOP.
`--chat-send` проверяет настоящую модель на одобрениях, отказе и правке,
но заменяет SMTP тестовым адаптером. Эти команды настоящих писем не отправляют.

Отдельные opt-in проверки меняют состояние настоящего ящика:
`--mail-read-state` временно меняет флаг одного письма и восстанавливает его;
`scripts/smoke_mail_delete.py` создаёт собственное UUID-письмо через IMAP APPEND,
проверяет корзину и очищает только свой UID. Существующие письма не удаляются.
Результаты сохраняются в `data/smoke/`, вне Git.

Для проверки интерфейса без настоящей почты и платных моделей:

```bash
uv run python -m tests.e2e.demo_server
```

[Демостенд](http://127.0.0.1:18764): `demo` / `demo-inbox-only`.
Он явно помечен, использует тестовые адаптеры и отдельную БД, не читает `.env`.
Демо-MP3 — синтетический тон для проверки плеера.

Фактические результаты: [docs/verification.md](docs/verification.md).
Ручная проверка: [docs/final-checklist.md](docs/final-checklist.md).

## Ограничения и хранение данных

- Один владелец, один INBOX, один процесс и локальная SQLite. Нет регистрации,
  refresh-токенов, полнотекстового поиска и просмотра других почтовых папок.
- Удаление почты требует IMAP MOVE и однозначной папки с флагом `\Trash`.
  Используются конкретные UID/UIDVALIDITY, без общего EXPUNGE. Корзину можно
  открыть и восстановить письмо через почтового провайдера. У агента инструмента удаления нет.
- Черновики ответов и исходящие сохраняются локально. Входящие вложения показываются
  как метаданные; исходящие файлы передаются SMTP, их содержимое не отправляется ИИ.
  HTML-письма не отправляются, CC/BCC нет. Несохранённые правки редактора требуют сохранения.
- JPEG/PNG: до `MAX_UPLOAD_MB` и 20 млн пикселей. Аудио: до `MAX_UPLOAD_MB` и пяти минут.
  Озвучка: до 5000 символов. Для сумм и похожих букв OCR нужна проверка человеком.
- Стриминг работает в чате; сводки, дайджесты и подготовка TTS ждут полного ответа.
  Контекст ограничен 12 последними пользовательскими ходами; обычные списки — 500 записями.
- Ежедневный дайджест создаётся один раз за локальную дату. Автоматического платного
  повтора после ошибки в тот же день нет; ручная генерация создаёт отдельный дайджест.
- По умолчанию MP3 хранятся семь дней (`AUDIO_RETENTION_DAYS`). Изображения,
  вложения и остальные данные эта очистка не удаляет. Для резервной копии останови
  приложение и скопируй `data/` в безопасное место.
- Markdown очищается DOMPurify, внешний HTML показывается текстом, изображения
  из ответов автоматически не загружаются. CDN требует интернета; Tailwind Play CDN
  выбран для учебного локального приложения, не production-развёртывания.
- Приложение слушает localhost. Для публичного размещения нужны отдельная настройка
  HTTPS, `AUTH_COOKIE_SECURE=true` и пересмотр модели доступа.

`.env`, локальная спецификация, БД, письма, вложения, аудио, логи, скриншоты
и материалы написания статьи остаются вне Git. Публикуются код, безопасный
`.env.example` и синтетические тестовые fixtures.
