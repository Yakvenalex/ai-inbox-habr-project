# Решения реализации

- 2026-11-11: Python 3.13, зависимости в `uv.lock`; один процесс FastAPI, без Node.js.
- Domain — dataclasses; application — сценарии и Protocol; SQLAlchemy скрыта за UoW.
  API и SDK tools используют одни сценарии. Сетевые операции выполняются вне транзакций.
- JWT HS256 проверяется одинаково для Bearer и cookie. Явный неверный header не
  переключается на cookie. Cookie-записи требуют Origin и CSRF claim; вход проверяет Origin.
- Срок задачи — точный timezone-aware datetime или отсутствие срока. Дата без времени
  отвергается; агент обязан уточнить время. В базе — UTC, в интерфейсе — APP_TIMEZONE.
- Первый вертикальный сценарий: миграция → вход → создание/завершение задачи → UI/API.
  Восемь интеграционных тестов прошли без сети и платных запросов.
- Состояние дайджеста сохраняется до сети: generating → ready/failed. Плановые ключи
  `scheduled:<дата>` уникальны, ручные и агентные ключи независимы. После перезапуска
  прерванные генерации отмечаются failed; автоматического платного повтора нет.
- Инструменты ограничивают операции явным намерением текущего сообщения. Инструкция
  внутри письма не даёт прав на запись. Для продолжения неясной команды агент уточняет
  действие. Это дополнительная простая защита, а не доказательство полной защиты LLM.
- Текст, результат и ID инструмента показываются раздельно: фраза модели об успехе
  не заменяет запись в БД. Семантический ключ внутри запроса ловит одинаковые вызовы.
- JPEG/PNG декодируются и заново сохраняются без EXIF; имена файлов — UUID.
  Аудио нормализуется ffmpeg в OGG Opus, до 5 минут; WebM проверяется отдельно.
- Нормализация речи выполняется детерминированно: даты, время и рубли/копейки,
  без дополнительного запроса к LLM. Контрольные примеры покрыты тестами.
- Браузерная проверка выявила Origin:null при Referrer-Policy:no-referrer у формы
  входа. Используется same-origin; проверка Origin и CSRF остаётся обязательной.
- 36 offline-тестов прошли. Реальные IMAP и TTS/WebM ASR прошли smoke. Vision/tool
  smoke пока не пройден: модель отвергнута при неверных полях инструмента, затем
  вернула пустой ответ. Причина исследуется; это не засчитывается как готовность.
- Итог диагностики vision: аргумент схемы инструмента `title` заменён на `task_title`,
  а тонкий адаптер переводит его обратно. Повторная реальная проверка прошла:
  одна запись в БД, правильные номер/копейки/срок, финальный ответ с ID. Точная причина
  потери исходного поля внутри маршрута не установлена; это совместимый обход.
- Добавлено отдельное уникальное ограничение `(request_id, tool_call_id)` и сохранение
  квитанций в модельном контексте после перезапуска. Повторный call ID с изменёнными
  аргументами не меняет первоначальный результат. Политика HTTP-сбоев не повторяет tools.
- Ограничение загрузки применяется до multipart-парсинга, включая chunked body.
  Реальный пароль/ключ не появляются даже в стандартном тексте ошибки Pydantic.
- Браузер проверил изображение, ASR-подтверждение, MP3 и дайджест на синтетическом стенде.
  Аппаратный микрофон остаётся ручной проверкой: среда не завершила запрос разрешения.

- 2026-11-11, UI: графитовая тема в духе ChatGPT с тёмной боковой панелью и белыми
  основными кнопками. Небольшой общий слой prose оформляет Markdown без frontend-сборки.
  [Marked 17.0.1](https://marked.js.org/) парсит текст, DOMPurify 3.4.17 очищает
  результат по списку разрешённых тегов. CDN-версии и SRI закреплены. Исходный HTML
  показывается текстом, внешние картинки не создаются, ссылки ограничены безопасными
  протоколами. Оригинальный Markdown сохраняется в БД и используется для озвучки.
- Сводка остаётся временной панелью: крестик останавливает аудио и очищает текст,
  источники и плеер без API-запроса. Карточки дайджестов/черновиков показывают короткий
  обычный текст без Markdown-разметки; полные ответы и дайджесты форматируются.

- 2026-11-11: новый запрос владельца расширил исходную версию ручной отправкой.
  Запрет автоматической отправки агентом сохраняется: prepare_outgoing_email вызывает
  общий Outbox.save, а send доступен отдельному API/UI после явного подтверждения.
- Исходящие — отдельная сущность от ответных Drafts. Есть recipient, subject, body,
  Message-ID, вложения и статус. DeliveryAttempt хранит уникальный request_id и квитанцию.
  Состояние sending фиксируется до SMTP; сетевой вызов выполняется вне транзакции.
- Подтверждение связано с хешем проверенных recipient/subject/body/attachment_ids.
  Изменившееся письмо нельзя отправить по старому подтверждению. Повтор того же request_id
  возвращает исходную квитанцию даже после последующих попыток.
- SMTP SSL через стандартную библиотеку в pool из двух потоков. Автоматических retries
  нет. Явный отрицательный SMTP-ответ → failed; потеря связи при DATA → unknown.
  Незавершённая попытка после перезапуска → unknown. После unknown повтор заблокирован.
- Один получатель, без CC/BCC. До 10 файлов суммарно до 15 МБ; после MIME-кодирования
  письмо увеличивается. Файлы сохраняются под UUID.bin, оригинальное безопасное имя —
  в метаданных. Загрузка не исполняет и не передаёт их содержимое ИИ. Выдача — attachment.
- AI compose использует выбранную модель без tools и возвращает JSON subject/body.
  Результат проверяется и остаётся редактируемым. Агентный tool готовит локальный черновик
  только если адрес явно присутствует в сообщении пользователя; send-tool отсутствует.
- Реальные smoke: SMTP TLS/login/NOOP прошёл без отправки, compose и исходящий tool
  выбранной модели прошли на синтетическом тексте. Доставку нового письма без выбранного
  пользователем получателя не проверяли; SMTP 250 не называется доказательством доставки.

- 2026-11-11: по запросу владельца UI синхронизирует прочитанность через IMAP. Сам GET
  остаётся без эффекта; после показа письма UI делает защищённый POST read-state.
  Agent tools, summary/digest и создание черновиков не вызывают этот сценарий.
- Записывающий MailStatusGateway отделён от порта чтения. Адаптер проверяет UIDVALIDITY
  и существование UID, выполняет только +FLAGS.SILENT/-FLAGS.SILENT для \Seen и повторно
  читает FLAGS. Не вызывает CLOSE/EXPUNGE. Молчаливо проигнорированный STORE — ошибка,
  а не успешная локальная отметка. Повтор целевого статуса идемпотентен.
- Числа писем берутся из IMAP STATUS без SELECT. Сбой счётчика не скрывает успешно
  полученный список. Групповая операция до 20 писем возвращает результат каждого,
  поскольку IMAP не даёт транзакции для группы. Старые ответы списка не затирают новые.
- Реальная smoke-проверка переключила статус одного письма и подтвердила его с другого
  соединения. Исходные флаги восстановлены в finally, остальные флаги сохранены.
  Содержимое письма не выводилось, письма не отправлялись, платные модели не вызывались.

- 2026-11-11: удаление диалога — отдельный защищённый DELETE use case, без tool агента.
  Custom список вместо native select позволяет разместить доступные отдельные кнопки
  открытия и удаления; подтверждение — нативный dialog с безопасным фокусом на отмене.
  Сообщения, sdk_history, chat_runs и actions удаляются одной транзакцией, без лимита
  списка 500. Задачи/черновики/исходящие/медиа самостоятельны и сохраняются.
  Общая блокировка с chat и проверка running защищают активный запрос от удаления.
  Удаление текущего диалога открывает новый; удалённая закладка обрабатывается как 404.

- 2026-11-11: панель ввода использует inline SVG: скрепка (JPEG/PNG), микрофон
  (запись/стоп) и говорящий смайл (загрузка аудио). Кнопки доступны с клавиатуры,
  имеют title/aria-label; busy сохраняет DOM иконки после распознавания.

- 2026-11-11: для полей тёмной темы задаём background-color вместо background,
  чтобы сохранять background-image со стрелкой daisyUI select.

- 2026-11-11: карточки писем получают min-width:0: иначе минимальная ширина
  grid-элемента раздвигала страницу (443 px при доступных 375 px). Мобильная
  навигация переносит кнопки вместо отдельной горизонтальной прокрутки.
  Общий overflow-x:hidden не используется: таблицы и код сохраняют локальный скролл.
