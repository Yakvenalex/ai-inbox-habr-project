# Материал для статьи (не черновик статьи)

1. Проблема: письмо → конкретное действие, без автоматической отправки почты.
2. Чистая архитектура на примере `Task`, `Tasks.create`, `SqlUnitOfWork`, API.
3. Один владелец: JWT в Swagger, HttpOnly-cookie и CSRF в браузере.
4. IMAP readonly, UIDVALIDITY, ограничение контекста и недоверенные письма.
5. Agents SDK и реальные прикладные инструменты; подтверждённые ID и идемпотентность.
6. Изображение → vision, голос → подтверждение текста, ответ → MP3.
7. Сохранённый дайджест, локальное расписание и ограничения сна компьютера.
8. Воспроизводимый запуск и offline-тесты; отдельные платные smoke-проверки.

Сквозная синтетическая демонстрация: счёт ЖЮ-3082 на 89 406,75 руб.,
проверка 19 ноября 2026 года в 09:20 по Москве → задача → локальный черновик → дайджест.
Секреты и настоящие письма не использовать в скриншотах.

Проверенные факты по этапам:
- Миграция пустой SQLite, восемь тестов авторизации и задач прошли.
- Подключение к моделям и почте проверяется отдельно, результаты не подменяют тесты.

Фрагменты для объяснения по готовому коду:
- `infrastructure/mail/imap.py`: ID и BODY.PEEK вместо порядкового номера.
- `application/tools.py` и `tasks.py`: один сценарий, атомарная квитанция, повтор без дублей.
- `infrastructure/ai/assistant.py`: Chat Completions, отключённый tracing, schema adapter.
- `application/chat.py`: отдельный текст модели и подтверждённые действия, восстановление.
- `application/speech_text.py`: детерминированные даты/копейки перед TTS.
- `presentation/api/dependencies.py`: единая JWT-проверка и CSRF только для cookie.
- `application/digests.py`: сохраняем состояние до сети, уникальный плановый день.

Проверено в реализации: реальный IMAP без изменения флагов, реальный TTS → WebM → ASR,
реальный vision → tool → запись в SQLite с правильными ЖЮ-3082, 89 406,75 и сроком.
Первый запуск vision выявил несовместимость поля title; task_title на границе SDK
помогло пройти проверку. Это наблюдение маршрута, не утверждение о внутреннем коде шлюза.
Статья должна показать и этот диагностический эпизод, и оставшиеся ограничения.

UI-доработка: тёмная тема, закрываемая сводка и единый безопасный рендерер Markdown
для сводок, диалогов и дайджестов. Показать разницу между парсингом Marked и очисткой
DOMPurify; тестовые HTML-инструкции и картинки не должны исполняться или загружаться.

Расширение после первой версии: ручная отправка с подтверждением, AI по наброску и файлы.
Показать `Outbox.send` как границу внешнего эффекта: запись попытки до сети, один SMTP-вызов,
квитанция после него, неизвестный результат после обрыва DATA. Объяснить разницу между
SMTP-приёмом и доставкой, а также content_token проверенного письма. Сквозная демонстрация —
только синтетический адрес и fake SMTP; реальный SMTP smoke использует login/NOOP.

Синхронизация прочитанности: противопоставить чистый GET для агента и отдельный
пользовательский POST → UID STORE → проверка FLAGS. Объяснить UIDVALIDITY, почему нельзя
перезаписывать весь набор флагов и почему не нужен локальный зеркальный статус в SQLite.
UI-демо: открыть → исчезновение из непрочитанных → вернуть непрочитанным → групповая отметка.

Удаление диалогов: крестик в доступном списке, подтверждение, атомарная очистка
зависимой истории и сохранение результатов работы. Разобрать гонку удаления с ответом
агента и почему bulk DELETE не должен использовать ограниченный list репозитория.

Разбор реального сбоя: проверка намерения не распознала «отправь на почту»,
а модель затем вернула пустой финальный текст. Показать две независимые причины,
регрессионный tool cycle SDK и честное отображение частичного результата без ретрая мутаций.

Отправка после подтверждения в чате: показ фактического snapshot, краткое отдельное
согласие, проверка в application без LLM, token версии и UUID SMTP-попытки. Показать
изменение черновика между просмотром и подтверждением, перезапуск и unknown при обрыве.
Демонстрация: настоящая модель с fake SMTP, без писем реальным получателям.

Озвучка одной кнопкой: автозапуск, квадрат Stop, одна активная сессия и гонка с
поздним ответом. Показать offline Node-тесты контроллера, кеш готового файла и
разницу между остановкой браузерного звука и отменой генерации у провайдера.


Поток агента: Runner.run_streamed → публичные дельты → POST SSE → очищенный Markdown.
Показать разницу между предварительным текстом и done после commit, прогресс tools,
перезагрузку с тем же request_id и отсутствие второго внешнего эффекта. Объяснить
ограниченный replay/snapshot в одном процессе, heartbeat, отказ от retries после
частичного потока и восстановление interrupted после остановки процесса. Для скриншота
использовать медленный синтетический демостенд, для интеграции — отдельный реальный smoke.
Диагностический эпизод: недоступный прокси окружения затронул оба режима, direct
/models подтвердил доступность API; явная настройка клиента помогла локализовать причину.


Удаление на сервере: ручное подтверждение → узкий MailDeletionGateway → UID MOVE
в обнаруженную \Trash. Показать выбор нескольких писем, частичный результат и повтор
без дублей, UIDVALIDITY и отказ от общего EXPUNGE. Отличать удаление из INBOX от
необратимой очистки и сохранённой локальной истории. Реальная демонстрация — только
собственное UUID-письмо APPEND, проверка корзины с другого соединения, точная очистка.
Разобрать наблюдение старых FETCH-флагов и проверку актуального UID через SEARCH.
