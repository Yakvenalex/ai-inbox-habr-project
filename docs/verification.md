# Результаты проверок

Финальная ревизия: **16 ноября 2026 года**, Python 3.13. Проверки ниже разделены
по способу выполнения: обычные тесты, реальные адаптеры и ручная проверка владельцем.
Они подтверждают перечисленные сценарии, не общую надёжность или подлинность моделей.

## Автоматические проверки

- **188 Python-тестов**: domain/application boundaries, JWT, cookie/CSRF/Origin,
  задачи, черновики, media, API, миграции и тестовые почтовые/AI-адаптеры.
- **28 JS-тестов**: чтение SSE, реконнект/snapshot, ошибки потока, управление
  воспроизведением и поздними TTS-ответами, несохранённые правки редакторов.
- Ruff, проверка форматирования, mypy и синтаксис браузерных JS-файлов.
- `uv lock --check --offline`, сборка wheel и исходного архива.
- Миграции чистой временной SQLite до актуального head и проверка существующей схемы.
- Проверка состава Git и архивов: локальные настройки, БД, почта, артефакты
  и материалы написания статьи не публикуются. Текущие значения четырёх секретов
  не обнаружены в отслеживаемых файлах и доступной локальной Git-истории.

Обычные pytest-тесты блокируют внешние соединения и используют временные данные.
Они не расходуют баланс и не отправляют настоящие письма. Запуск:

```bash
uv run pytest -q
uv run ruff check src tests scripts migrations
uv run ruff format --check src tests scripts migrations
uv run mypy
node --test tests/frontend/*.test.cjs
uv run alembic check
```

Особенно проверяются: отправка только версии из предыдущего показа, отзыв после
нового просмотра, изменённые адрес/текст/вложения, несколько черновиков, другой
диалог, конкурентные подтверждения и повтор request_id. Ошибки модели до tools
не отправляют письмо; ошибки после SMTP сохраняют его фактическую квитанцию.
Состояние unknown не разрешает повтор. Выбор намерения делает агент; тесты с fake
моделью проверяют механику приложения, а не качество понимания языка.

IMAP-тесты покрывают UIDVALIDITY, BODY.PEEK, пагинацию при новых и удалённых письмах,
Seen, точный MOVE, обнаружение Trash, частичные ошибки группы и отсутствие общего
EXPUNGE/CLOSE. SSE-тесты проверяют сохранение перед done, отключение браузера,
повтор после очистки кеша, ограничение памяти и восстановление прерванного запроса.

## Ограниченные реальные проверки

16 ноября с `cx/gpt-6.1-terra`:

- Потоковая генерация: 107 фрагментов текста, вызов инструмента и одна учебная
  задача во временной БД. Настоящие письма не отправлялись.
- `scripts/smoke.py --chat-send`: четыре сценария — «отправляй. пойдет», другое
  одобрение по смыслу, отказ и правка. Агент вызвал send в первых двух, в остальных
  не вызвал; повтор request_id не повторил действие. LLM настоящая, SMTP тестовый,
  адрес и данные синтетические. Это платная opt-in проверка, не обычный тест.
- Финальная `scripts/smoke.py --mail --smtp`: выборка из трёх настоящих писем,
  чтение без изменения флагов и SMTP TLS/login/NOOP прошли. Содержимое писем
  не выводилось; AI не вызывался и настоящие письма не отправлялись.

Ранее проверены настоящие адаптеры:

- IMAP: ограниченная выборка/чтение без изменения флагов, две страницы без дублей.
- IMAP MOVE: собственное UUID-письмо через APPEND, перенос в серверную корзину,
  повтор, подтверждение отдельным соединением и очистка только своего UID.
  Существующие письма не удалялись, общий EXPUNGE не выполнялся.
- SMTP: ранее владелец подтверждал получение тестового письма. Это не новая
  проверка доставки с вложениями 16 ноября.
- ASR `dg/nova-3`: настоящий русский голосовой файл и WebM после конвертации.
  TTS `anyvoice/builtin-7`: настоящий MP3. Эталон для измерения WER не готовился.

Реальные AI-проверки платные и запускаются явно. Наличие ID в каталоге не доказывает
доступность маршрута; отказ или timeout не засчитываются как успешная проверка.
Во время финальной чистки рабочие сетевые адаптеры не менялись, повторные платные
генерации и отправка реальных писем для публикации не требуются.

## Браузер и ручная проверка

На отдельном стенде 18764 с синтетическими данными проверены вход, Markdown,
источники, задачи, карточки исходящих, подтверждение, прогресс и восстановление
потока после reload, управление TTS, пагинация 20 → 25, несохранённые редакторы,
подтверждения удаления письма и диалога. В этой демонстрации LLM/IMAP/SMTP/TTS —
тестовые адаптеры; она не подтверждает работу настоящего микрофона или доставку.
Рабочие `/health`, страница входа, Swagger и защищённый API проверяются отдельно.

16 ноября Алексей подтвердил ручные сценарии рабочего приложения:

- Подготовка и подтверждение исходящего письма через чат; скриншоты сохранены владельцем.
- Фото учебного счёта → задача: ЖЮ-3082, 89 406,75 ₽, 19 ноября 2026, 09:20 по Москве.
- Голосовой сценарий с уточнением: «В половине десятого утра, по Москве» →
  17 ноября 2026, 09:30; ID в чате совпал с карточкой задачи.
- Дайджест по учебным письмам с действием, встречей и справочной информацией.

Эти пункты записаны по сообщениям/скриншотам владельца, а не как независимый
автоматический прогон. Доставка нового вложения, системное закрытие вкладки
с beforeunload и фактическое срабатывание расписания требуют отдельной ручной
проверки при необходимости; как подтверждённые здесь не заявлены.
