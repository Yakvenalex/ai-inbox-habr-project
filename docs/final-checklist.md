# Финальная ручная проверка

Рабочее приложение: http://127.0.0.1:18763. Сначала обнови страницу.
Проверки моделей платные. Для скриншотов и проб удаления используй синтетический
стенд `uv run python -m tests.e2e.demo_server` (18764, demo / demo-inbox-only).
Он содержит 25 учебных писем. Реальные письма и секреты в демонстрации не показывай.

- [ ] Вход и Swagger: войти в UI; открыть Swagger в новой вкладке, Authorize,
      выполнить auth/me. Без авторизации защищённый endpoint возвращает 401.
- [ ] Входящие: «Все письма», «Загрузить ещё», обновление к последним письмам.
      Старые страницы не дублируют новые; выбор ограничен 20 письмами.
      На демостенде счётчик показанного меняется 20 → 25, кнопка исчезает.
- [ ] Прочитанность: открыть письмо, убедиться в изменении статуса в почтовом клиенте;
      отметить непрочитанным обратно. Провайдерский интерфейс может требовать обновления.
- [ ] Корзина: сначала отменить подтверждение; затем удалить учебное письмо и проверить
      серверную корзину. Реальное письмо выбирай только если действительно хочешь убрать его.
- [ ] Сводка и чат: проверить Markdown, закрытие сводки, частичный потоковый ответ,
      reload во время генерации и историю без дубликата. ID действий сверять с карточками.
- [ ] Задача и изображение: tests/fixtures/invoice.png → задача со счётом ЖЮ-3082,
      89 406,75 руб., сроком 19 ноября 2026 года 09:20 по Москве. Сверить вручную.
- [ ] Голос: запись именно аппаратным микрофоном, разрешение браузера, исправление
      расшифровки, отдельная отправка. До отправки ASR сама не выполняет команду.
      Аппаратный микрофон в автоматизированном браузере пока не подтверждён.
- [ ] Озвучка: автозапуск AnyModel после подготовки; квадрат Stop во время ожидания
      и воспроизведения; поздний файл не начинает играть после остановки.
- [ ] Письмо: заполнить вручную/ИИ, приложить учебный файл, сохранить и перезагрузить.
      Несохранённые правки → «Новое»/ссылка/выход → «Остаться» оставляет текст.
      В ответном черновике сначала сохранить правки, затем подготовить к отправке.
- [ ] Реальная отправка: выбрать собственный проверочный адрес и явно подтвердить
      письмо в редакторе или чате. Проверить содержимое и вложения у получателя.
      SMTP accepted сам по себе не доказывает доставку. При unknown повтор не разрешён.
      Обычные тесты и текущий обзор настоящих писем не отправляют.
- [ ] Дайджест: ручная генерация, источники, озвучка; расписание сверить с .env.
      Для ежедневного запуска компьютер и приложение должны работать.

При ошибке зафиксировать сценарий, ожидаемое/фактическое поведение и время.
Не включать секреты и реальные письма в Git/публичные скриншоты.
